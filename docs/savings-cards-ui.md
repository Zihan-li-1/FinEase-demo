# 消费卡片 UI 重构验收

本次只重构储蓄计划中的「消费习惯观察」和「分类消费建议」。运行入口为
http://127.0.0.1:4300/ ，已重建并替换本地 Web 生产容器。

## 显示结构

- 原观察卡：纵向堆叠类别、长句趋势解释、逐卡来源和证据月份。
- 新观察卡：双列等宽卡片，依次显示类别、最近月金额、实际差额和带箭头的增减状态。
- 原建议卡：最近月到建议金额的行内对比，以及重复的原因、来源、执行确认说明。
- 新建议卡：双列卡片，建议上限为主数字，最近月金额为次要数字；区域顶部统一显示一次待确认说明。
- 两区各有一个默认折叠的「计算依据」，集中展示来源、实际有效月份、样本数和均值。
- 容器可用宽度不超过 380px 时降为单列。样式只作用于储蓄计划，原输入卡共用样式保留。

## 数据与兼容

`server/savings-advisor.mjs` 只增加已复核 `comparisons` 的响应投影与完整月份列表。
历史均值、阈值、分类合计、预算金额、可行性和资金缺口的计算全部保持不变。
模型提示、Agent 路由、Core 操作与安全确认均未修改，页面不写入预算或添加采纳按钮。

卡片颜色表示实际金额差额的正负；服务端原有按阈值区分的趋势保留在计算依据中。
例如差额为 +¥50、仍在既有趋势阈值内时，卡片展示红色 +¥50，依据仍显示原来的「与历史接近」。
零历史均值不计算百分比，因此可正常展示金额差额。真实零记录参与均值，缺失类别月份不补零。
不足一分钱的非零差额使用 `+<¥0.01` 或 `−<¥0.01`，避免伪装成持平。

缺少比较聚合的旧聊天快照显示「数据不足」；不会从长句、抽样证据引用或静态种子猜测均值。
重新生成计划后即可取得完整聚合。异常或缺失金额不显示为零、NaN 或 Infinity。
已移除前端逐卡 `reason`、`evidenceLabel` 和重复确认文案；服务端 `reason` 合同保留供既有调用方兼容。
